# ADR 005: GPU acceleration strategy (whisper.cpp CUDA)

**Status:** Decided  
**Date:** 2026-05-20  
**Deciders:** owner (M4 iteration)  
**Supersedes:** none  
**Related:** ADR 001 (engine), ADR 002 (Compose), UNKNOWNS U2

## Context

CPU transcription of large MP4 files is slow but acceptable for v1 (RISK_REGISTRY R5). Operators with NVIDIA GPUs may want faster offline runs without changing the CLI contract (FR3, SPEC R1–R6). U2 asked whether to add a GPU/CUDA Docker variant using whisper.cpp CUDA or adopt faster-whisper.

Constraints from existing decisions:

- ADR 001 chose **whisper.cpp** + `whisper-cli`; rejected faster-whisper for v1 due to Python/CUDA stack complexity.
- ADR 002 requires an **additive** Compose profile; CPU default path must remain the primary, documented workflow.
- M4 scope (master plan §19): optional CUDA image; no faster-whisper unless this ADR revises engine choice.

## Decision

1. **Engine:** Keep **whisper.cpp**; do **not** adopt faster-whisper for M4.
2. **Delivery:** Separate **`Dockerfile.cuda`** built from `nvidia/cuda` devel base (or CUDA-enabled Ubuntu) with whisper.cpp compiled using **`-DGGML_CUDA=1`** (same `WHISPER_CPP_REF` pin as CPU `Dockerfile`).
3. **Runtime:** Compose **profile `gpu`** on a dedicated **`transcript-gpu`** service (same entrypoint/volumes as CPU `transcript`, `Dockerfile.cuda` build); require NVIDIA Container Toolkit on the host. Default profile remains CPU (`dev`).
4. **CLI:** Unchanged — `./bin/start.sh transcribe …` and `transcribe-all`; GPU invoked via documented `compose --profile gpu` (or `bin/start.sh` wrapper added in M4-T2/T3).
5. **CI:** GHA stays **CPU-only**; GPU verify is manual on owner hardware (no NVIDIA runners in default workflow).
6. **Rollback:** Stop using `--profile gpu`; continue CPU image. Revert `Dockerfile.cuda` and compose profile changes without touching CPU `Dockerfile`.

## Consequences

**Positive**

- Same entrypoint, volumes, and artifact layout as CPU path (FR3, R4).
- Reuses pinned whisper.cpp tag and existing model volume.
- Additive — does not break smoke/validate on default branch.

**Negative**

- Larger GPU image; longer first build (CUDA toolkit + compile).
- Host must install NVIDIA driver + [NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/install-guide.html).
- `CMAKE_CUDA_ARCHITECTURES` may need tuning per GPU generation (document in README).
- No automated GPU smoke in CI.

## Alternatives considered

| Alternative | Rejected because |
|-------------|------------------|
| faster-whisper (Python + CUDA) | Second runtime, deps, and ops surface; contradicts ADR 001 unless explicitly revised; out of M4 plan scope |
| Single Dockerfile with CUDA optional arg | Harder to keep CPU image slim and CI fast; two Dockerfiles clearer for operators |
| GPU as default service | Breaks hosts without NVIDIA; violates “CPU path unchanged” acceptance criteria |
| Cloud GPU | Out of product scope (offline, local) |

## Implementation notes (for M4-T2)

- Upstream build (whisper.cpp v1.8.4+): `cmake -B build -DGGML_CUDA=1` (optional `-DCMAKE_CUDA_ARCHITECTURES=…` for target GPU).
- Compose: `profiles: [gpu]` on service `transcript-gpu` with `build.dockerfile: Dockerfile.cuda`; deploy `resources.reservations.devices` for NVIDIA GPU (Compose v2 syntax).
- Keep `USER transcript` and non-root pattern from M1-T4.
