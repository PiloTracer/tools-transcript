## 1. Executive Summary

**tools-transcript** is a local CLI tool that extracts transcripts (`.txt` + `.srt`) from video and audio files using **whisper.cpp** inside an **isolated Docker** stack. The operator drops media in `./sources`, runs `./bin/start.sh transcribe <file>`, and collects artifacts from `./outputs`. No cloud upload, no database, no web UI in v1.

Foundation delivered a working stack (Dockerfile, compose, entrypoint, audio smoke test). This plan delivered **v1 hardening** (M1), **CI** (M2), **operator UX** for large files (M3), and **optional GPU acceleration** (M4). All four milestones complete as of 2026-05-20. Top risks: CPU slowness on large MP4 (accepted; GPU optional), upstream whisper.cpp drift (mitigate via pin + CI), model download offline (document + `ensure-model`).

## 5. Constraints

- **Local-only processing** of user media — no upload to third-party transcription APIs (ADR 001).
- **Docker required** on host — no bare-metal whisper install path in v1 (ADR 002).
- **Single-user CLI** — no auth, DB, or multi-tenant (ADR 003).
- **Protected files** — agents must not change `docker-compose.yml`, `Dockerfile`, `.env*` without explicit owner approval in message (`.cursorrules`).
- **No PII in logs** — transcript content must not appear in logs (SPEC R5).
- **Foundation waivers W1–W4** must close in M1 before v1 sign-off.

## 9. Architecture Overview

Reference: `.work/plans/foundation/20260520-04-foundation-architecture.md`

```text
Operator (host)
  ./sources/  ./outputs/
       │            ▲
       ▼            │
  bin/start.sh ──► docker compose run --rm transcript
                         │
                         ▼
                   app/entrypoint.sh
                     ├─ ffmpeg (video → wav)
                     └─ whisper-cli → .txt / .srt
```

**Bounded contexts:** `transcription` (entrypoint), `stack` (`bin/start.sh`, compose). No database. No published ports in v1.
